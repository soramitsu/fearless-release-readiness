# Passkey enabled-feature acceptance

Run `node scripts/audit-passkey-enabled-acceptance.mjs` as part of the final live release audit. It takes no production flags or path overrides. A missing shipping manifest, reviewer trust policy, attestation, or raw evidence fails the gate. Passing prerequisite or blocked-state checks does not pass this gate.

The release-unblock bundle's individual passkey production-smoke command currently runs only the service smoke. It cannot establish enabled recovery acceptance by itself; use the full aggregate live audit until that bundle command and its exact-command fixtures are reconciled.

The reviewed detached `config/release-shipping-manifest.json` must have `schemaVersion: 1`, `googleApplicationId`, `passkeyConfigSha256`, and `android` and `ios` objects containing exact `sourceCommit` (lowercase Git SHA-1), `artifactSha256` (lowercase SHA-256), and `compiledPasskeyRecoveryEnabled: true`. The [shipping manifest audit](release-shipping-manifest.md) runs first in the full-live audit and binds clean source/dependency commits, routes, policies, distribution identity, artifacts, and evidence. This gate hashes the entire raw manifest and requires those mobile source, artifact, and compiled-approval identities to match its signed acceptance payload. It also hashes `config/passkey-backup-production.json` and requires the global and both platform `releaseEnabled` flags to be true, with Google Drive app-data as primary storage on each platform.

Provision `config/passkey-enabled-acceptance-trust.json` through the normal reviewed source process. It has `schemaVersion: 1` and `keys.mobileQa` and `keys.security`, each with a unique `keyId` and Ed25519 `publicKeyPem`. The roles must belong to independently authorized reviewers. Never place private keys in the workspace, CI variables visible to app builds, or chat. A self-signed fixture or two signatures from one person is not independent review. Protected CI must verify the exact shipping commit, public-key changes, and artifact digests.

The ignored `build/reports/passkey-enabled-acceptance/attestation.json` has `schemaVersion: 1`, `payload`, and exactly two Ed25519 signatures. Each signature covers UTF-8 bytes of `fearless/passkey-enabled-acceptance/v1\n` followed by recursively key-sorted compact JSON of the payload. Signatures are Base64 of the raw 64-byte Ed25519 signature and bind the named role and trusted key ID. The payload contains the complete release-manifest SHA-256, exact Android/iOS source and artifact identities, `startedAt`, `completedAt`, and `expiresAt` timestamps, `googleDrive`, `checks`, and `evidence`. Acceptance expires no more than 14 days after completion.

`googleDrive` records the shared Fearless Google application ID, distinct Android and iOS OAuth client IDs, the exact shared app-data file ID and ciphertext SHA-256, and the `https://www.googleapis.com/auth/drive.appdata` scope. Reviewers must verify both clients can access the same file under explicit account selection and consent. Apple iCloud may be an additional copy; it cannot substitute for Drive recovery.

The signed `checks` object requires affirmative results for both replacement-device directions with original devices unavailable; identical wallet identity and original-key signing/export; native Google Password Manager PRF; current signed configuration enabled at ceremony time; upload, download and decryption; traffic inspection for absent PRF output, plaintext and keys; missing PRF, wrong account, revoked credential, tamper, replay, concurrent update and interrupted-upload cases; last decryptable generation retention; credential revocation and backup-key rotation; provider recovery; exact Play-signed and Apple-delivered in-place upgrades; and feature disablement preserving legacy wallet access. The device runs must use dedicated test wallets and separately approved spending caps for any funded transfer. Do not include phrases, PRF bytes, backup keys, or plaintext backups in the attestation or raw evidence.

`evidence` has exactly one unique `{kind,path,sha256}` record for each raw file category: `ios-to-replacement-android`, `android-to-replacement-ios`, `drive-appdata-interoperability`, `sanitized-network-traffic`, `play-signed-upgrade`, `apple-delivered-upgrade`, and `independent-security-review`. Files must be regular, non-symlink files below `build/reports/passkey-enabled-acceptance/raw/`; the gate verifies their exact bytes and rejects duplicate kinds, reused paths, traversal and substitutions. Store sanitized device/run identifiers, signed distribution receipt identities, result summaries and safe traffic inspection findings there; retain protected original recordings under operator access as needed for independent review.

The repository currently has no shipping manifest, reviewer trust keys, distribution-signed device runs, or signed enabled-feature attestation. Its production configuration still disables passkey recovery. The prerequisite and bundle contracts also assert this interim disabled policy; a reviewed release transition must update those contracts together with the actual enabled source and artifacts. Merely adding an attestation cannot turn the present candidate green. The gate is expected to fail until actual qualification is complete. Its 21 synthetic cases in `node scripts/test-passkey-enabled-acceptance.mjs` prove rejection behavior only; they are never acceptance evidence.
